## Hosted demo

The demo uses four services, all on free plans without expiry:

| Component | Service | Notes |
|---|---|---|
| Database (PostgreSQL + pgvector) | [Neon](https://neon.tech) | Free plan includes pgvector and does not expire. Render's free Postgres is deleted after 30 days. |
| API | [Render](https://render.com), defined by [`render.yaml`](../render.yaml) | One Docker web service, `docminds-api` |
| Frontend | [Vercel](https://vercel.com) | Next.js, root directory `frontend` |
| Models | [Groq](https://console.groq.com/keys) (answers), [Gemini](https://aistudio.google.com/apikey) (embeddings) | Free API keys |

## How the demo differs from local development

Locally, DocMinds runs an API, a Celery worker, Redis and a local PyTorch embedding model. Render's free plan cannot host that: background workers are not free, and a free web service has 512 MB of memory, less than PyTorch needs. `render.yaml` therefore sets two options:

- **`EMBEDDING_PROVIDER=gemini`**: embeddings come from the Gemini API. Render passes this value to the Docker build as well, and the image is built without PyTorch. The CI job *Free-demo image* verifies that this build imports the app without `torch` and stays under 300 MB peak memory.
- **`INGESTION_MODE=inline`**: the API processes each upload itself after replying, so no worker or Redis is needed. Uploads still return immediately and status still moves from `pending` to `completed`.

A free Render service loses its disk on restart, so original uploaded files are lost. Extracted text and embeddings are stored in Neon, so search and chat keep working; only the file preview is affected. Free services also sleep after 15 minutes idle, so the first request afterwards takes up to a minute.

## Deploying the demo

### 1. Create the keys and database

1. **Neon:** create a project (for example `docminds`, region AWS US West 2 / Oregon, close to Render's default). Open **Connect**, turn **Connection pooling** off, and copy the connection string.
2. **Groq:** create an API key at https://console.groq.com/keys.
3. **Gemini:** create an API key at https://aistudio.google.com/apikey.

Alembic's `env.py` runs `CREATE EXTENSION IF NOT EXISTS vector` before applying migrations, which Neon permits, so pgvector needs no manual setup. The app converts Neon's `sslmode` / `channel_binding` URL options for asyncpg itself.

### 2. Deploy the API on Render

1. Open https://dashboard.render.com/blueprints, choose **New Blueprint Instance**, and select this repository.
2. Provide the prompted values: `DATABASE_URL` (Neon), `GROQ_API_KEY`, `GEMINI_API_KEY`. Leave `FRONTEND_ORIGIN` empty for now. `SECRET_KEY` is generated by Render.
3. Apply. When the service is live, `https://<your-api>.onrender.com/api/v1/health` should return `"status": "healthy"` with `"api_key_configured": true` under `llm`.

`render.yaml` sets `ENV=production`, `DEBUG=false`, `LLM_PROVIDER=groq`, `GROQ_MODEL`, `EMBEDDING_DIMENSION=384`, retrieval defaults and Tesseract OCR. `AGENT_MODEL` and `AGENT_MAX_STEPS` are not set, so their defaults apply; add them under **Environment** to change them.

### 3. Deploy the frontend on Vercel

1. Import this repository at https://vercel.com/new.
2. Set **Root Directory** to `frontend`.
3. Add the environment variable `NEXT_PUBLIC_API_URL` with the Render API address, without a trailing slash.
4. Deploy and note the site address.

### 4. Allow the frontend origin

In Render, open **docminds-api → Environment** and set `FRONTEND_ORIGIN` to the Vercel address (comma-separated for several). Without it the browser blocks every request with a CORS error.

## Docker image

`backend/Dockerfile` builds the API image:

- Based on `python:3.11-slim` with `tesseract-ocr` and `tesseract-ocr-eng` installed.
- Build argument `EMBEDDING_PROVIDER` (default `local`). With `local`, the image installs `sentence-transformers` and pre-downloads `all-MiniLM-L6-v2`; with any other value, `sentence-transformers` (and therefore PyTorch) is omitted.
- The container runs `alembic upgrade head` and then `uvicorn app.main:app` on `$PORT` (default 8000).

```bash
docker build --build-arg EMBEDDING_PROVIDER=gemini -t docminds-api backend
docker run -p 8000:8000 \
  -e DATABASE_URL="postgresql://..." -e SECRET_KEY="..." \
  -e EMBEDDING_PROVIDER=gemini -e GEMINI_API_KEY="..." \
  -e GROQ_API_KEY="..." -e INGESTION_MODE=inline \
  docminds-api
```

## Self-hosting with a worker

To run with background ingestion (`INGESTION_MODE=celery`, the default):

- Provide Redis and set `REDIS_URL_OVERRIDE` (or `REDIS_HOST` / `REDIS_PORT`).
- Run a worker from the same image or codebase: `celery -A app.core.celery_app worker --loglevel=info`.
- The API and worker exchange only the document id; the worker reads the uploaded file from `uploads/`. They must therefore share a filesystem (same host or a shared volume).
- The embedding provider and `EMBEDDING_DIMENSION` must be identical in both processes.

## Production checklist

| Item | Why |
|---|---|
| Set `SECRET_KEY` (for example `openssl rand -hex 32`) | The default in `config.py` is public; anyone could forge tokens |
| `ENV=production`, `DEBUG=false` | `ENV=production` disables SQL statement echo; `DEBUG` is only reported by `/api/v1/health` |
| `FRONTEND_ORIGIN` set to the exact frontend URL, including scheme | CORS |
| `DATABASE_URL` points to Postgres with pgvector | Required for the `vector` column and HNSW index |
| `EMBEDDING_PROVIDER` and `EMBEDDING_DIMENSION` fixed before the first upload | Changing either later requires re-processing every document |
| Persistent storage for `uploads/` | Needed for file preview and for re-processing |

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Document `failed`, error mentions `GEMINI_API_KEY` | Key missing or mistyped | Set it under Render → Environment |
| Document `failed` with `HTTP 429` | Gemini free-tier rate limit | Wait a minute and upload again |
| CORS error in the browser console | `FRONTEND_ORIGIN` missing or different from the site address | See step 4 |
| First request takes about a minute | Free services sleep after 15 minutes idle | Expected on free plans |
| Deep research answers "could not finish" with a rate-limit error | Agent mode makes several Groq calls per question | Wait, use Quick answer, or lower `AGENT_MAX_STEPS` |
| `/api/v1/health` shows `"api_key_configured": false` | `GROQ_API_KEY` not set on the service | Set it and redeploy |
